# Field records in investigator search

Connected implementation on `feat/platform-build-batch`, extending docs135. No new migration or dependency. Runtime acceptance is **unrun**.

Case search now exposes separate `field_session` and `field_observation` kinds. Only the latest session/observation organisation version enters the search index; corrections and withdrawals stay retained and are reachable through history. Search matches declared title, purpose, summary, account, source description, category and basis. It does not index coordinates or infer location, event order or factual truth. Source/receipt filters continue using the directly linked immutable original rather than organisation time. Session status means a start/end record exists, not live team presence. Observation context status is separately labelled and never becomes a finding. An apparently current context review also requires its exact authority/access versions and current assigned reviewer.

The investigator can open a Field result directly without unlocking or creating a local Field vault. GET `/api/cases/:caseId/field-records/:captureId/context` returns a selected exact original, separately recorded context reviews and paged correction/session-original history (25/page). It checks the selected original bytes/manifest, compares the organisation record with those bytes and its saved request hash, and verifies the selected version’s linked attachment bytes and receipt metadata. Each displayed historical original is checked separately; other versions’ attachments require selection of that version. A newer head remains explicitly discoverable while inspecting an older original. Times, raw author/device/authority, separate organisation authority, previous-capture identity and content hash remain visible. The original viewer retains its existing audited download controls.

The shared organisation receipt reader now verifies raw record semantics, source identity/digests/times, request authority/reason hash, stored organisation time/version/predecessor and frozen attachment links before returning its receipt, including same-original POST retries. Predecessors must identify the immediately preceding version in the same session/observation chain. It also enforces source-use checks when that original has registered source metadata. Immutable originals and organisational records remain different records. No observation context review authorises release or promotion to a reviewed finding. The new context read is audited; mutation/review endpoints retain their own current controls.

The search transaction now holds the case lock so authority/membership updates cannot cross its source-use checks. All queries retain tenant+case joins. Client and unrelated-case access is denied. UI clears loaded context after access failure and aborts obsolete inspection requests. There is no third-party copy, new dependency, background collection or native/device claim.
