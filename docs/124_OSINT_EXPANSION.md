## Implemented operations

- The existing source-policy API now registers three independently versioned profiles: the unchanged company profile, `rdap_domain_v1`, and `supplied_webpage_v1`. Each new policy binds the immutable profile digest, explicit endpoint scope, `none:controlled-input` credential scope, purpose/basis/terms digest/minimisation/retention, maximum 30 attempts per five minutes and expiry. This is an internal conservative development cap, not an asserted provider allowance. Policy proposal, independent acceptance/rejection, withdrawal and supersession remain separate immutable records. The original company's serialized policy/receipt and independent verifier are unchanged; its profile digest remains `0b7dd5a9ba019c0a6a61c9a4071e3c664d6ca364fb6cfe25ecfcb3b228c60f1c`.
- Migration **065** introduces endpoint scopes, saved research request heads/immutable versions/terminal withdrawals, queued/running/succeeded/failed/cancelled runs, automatic immutable state events and original-linked captures. 066–069 remain unused/reserved. Same-tenant/case composite keys join request, authority, run, capture, original and source. Successful runs require a committed capture; terminal jobs cannot restart. Existing 061/062 data and schema contracts remain intact.
- Assigned reviewers save bounded requests against current case authority and independently approved source policy. Requests retain title/question, exact target, purpose/minimisation/retention, reason, actor, digest and expiry within 24 hours. Corrections append versions, never mutate prior requests. A new version makes queued older-version work ineligible. Any investigator with current case access can explicitly queue a selected version. Explicit re-runs create a new run and retain the previous run ID; no autonomous scheduling or retry.
- One fenced execution path handles supplied captures and the RDAP transport worker. It rechecks current requester membership, policy reviewer membership, request author membership, case lifecycle/authority, latest request and latest policy at start, during transport and at attachment. Durable quota reservations count attempted runs even when they fail; a restarted worker cannot reset the budget. Provider 429 backoff is retained per tenant/adapter controlled-input scope. Runs have 30-second leases, ten-second transport limits, cancellation and explicit expired-lease reconciliation. Original/object cleanup follows transaction rollback; an ambiguous commit is checked before deletion. State events and audit preserve failure history.
- The **fixed-endpoint RDAP transport and actual queued worker path** are implemented in `rdap-transport.ts` and `runResearchCapture`. HTTPS requests are bound to one candidate endpoint (`https://rdap.verisign.com/com/v1/domain/`, `.com` only); endpoint policy alone cannot activate them. `liveRdapQualified=false` rejects before DNS/socket access and is not an environment/API toggle. The candidate address is not a provider approval or coverage claim. Future activation requires code review plus policy/terms/runtime/transport qualification. The code pins a public resolved address, uses normal TLS validation, no ambient proxy/credentials, GET only, identity encoding, no redirects, response-length/truncation checks, 256 KiB bound and timeout/cancellation. There is no bootstrap, nameserver, entity, vCard, email, contact or linked-resource traversal.
- The explicit loopback adapter uses the **same bounded HTTP exchange** with only `127.0.0.1:<port>/domain/example.test`. Its logical policy endpoint is exactly `https://rdap.example.test/domain/`, and only `example.test` is accepted. The CLI starts its own ephemeral fixture server, consumes one previously queued `rdap_transport` run, closes its server and prints a fictional/no-provider receipt. No fixture API takes an arbitrary host or path. Worker output from a provider is also rejected while live activation remains disabled.
- RDAP supplied bytes must be bounded UTF-8 JSON with duplicate-key/nesting checks, a domain object and exact `ldhName` match. Extracted unreviewed assertions have exact JSON pointers for domain class/name, handle, statuses and registration-event action/date. Unknown fields, including incidental contacts, remain in immutable original bytes but are never expanded or followed. Original minimisation/retention still require review; preservation is not a promise that upstream bytes contain no personal fields.
- The supplied webpage workflow uploads original UTF-8 HTML/text up to 256 KiB with a policy-approved exact HTTPS origin and declared page URL, publisher, page/source time and retrieval time. Source time (including its original offset), declared retrieval time, server receipt and later rendering time are separate. No DOM, HTML execution, webpage fetch, screenshot, subresource fetch or inferred page timestamp occurs. Original downloads reuse the existing audited attachment/plain-text/nosniff route. A capture must explicitly declare fictional development data.
- Successful runs atomically create an immutable original, capture receipt and **unreviewed manual source record**. Existing independent metadata review and separate source-use decisions block new analysis/report use until approved. No capture creates a claim or finding. Source corrections and reviewed interpretations continue through existing interfaces.
- The connected workbench offers source selection, policy proposal/independent review/history/withdrawal, reviewer request authorisation/corrections/history, explicit version/run choice, supplied-file capture, RDAP fixture queueing, cancellation/recovery, visible failure/permission states, original inspection, explicit re-run and context download. The worker remains an operator CLI, as with the existing company fixture; queueing does not silently execute a collector. A different user must perform independent policy/source review.
- Frozen JSON report source-use proofs carry a separate `research` provenance envelope (original company `collection` format untouched). It binds the capture, original digest/time, exact request version/digest, historical case authority and endpoint policy/review. `tools/verify_research_context.py` is a standalone standard-library verifier for exported contexts; `verify_report.py` invokes it for frozen research proofs. It checks original bytes, pointer values, scope, modes, profile digests, independent policy review, quota/retention and permission chronology. Hash consistency does not verify actor identity, source truth, legal permission or current release approval.
