# Reverify frozen report sources

28 October 2026. Synthetic lab slice stacked on PR #25. A frozen file's digest proves its bytes have not changed; it does not prove that the current evidence store still contains its cited originals. This adds an explicit point-in-time check of that separate property.

POST `/api/cases/:caseId/report-revisions/:revisionId/verify-sources` with `{sha256}` requires an authenticated internal case member and CSRF. It rehashes the frozen report, binds the caller's fingerprint, validates its case/status and unique bounded finding IDs, then reconstructs only those findings using the existing report assembler. Current source byte lengths/digests, original-text eligibility, exact quote spans, accepted review linkage and acquisition policies are checked. The full reconstructed finding representation must equal the frozen one, including embedded bytes and reviewer/source/policy metadata. Missing records or changed representations fail closed. A legitimate reviewer display-name change can therefore require investigation rather than silently treating different metadata as equal.

The assembler still enforces its existing 1,000-item, 32 MiB output and bounded original-read limits. A repeatable-read database transaction provides a consistent record view; filesystem reads are separate sequential checks, not a filesystem snapshot. Later findings and working context are excluded, so corruption of an unrelated later source cannot invalidate the earlier report's source set. Current case scope and historical source policies are not asserted to be release-approved.

Successful verification inserts an audit event atomically before returning `{verificationId,caseId,revisionId,sha256,findingCount,status:'snapshot_sources_verified_not_released'}`. The event records the fingerprint and count, not source content. Failed checks/audit commit produce no successful receipt. Retries deliberately perform a fresh check and can produce distinct events. Success expires as a factual assurance as soon as relevant storage changes; it is not a reusable release token, signature, review decision or client grant. Frozen bytes remain unchanged even when current originals fail.

The Saved internal report revisions panel has a Reverify cited originals action and validates its response identity/fingerprint/status. Original download verification, independent offline verification and human internal review remain separate actions. No schema, dependency or third-party source change.
