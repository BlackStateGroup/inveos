# Portal browser acceptance harness

28 October 2026. Stacked on PR #30. This first-party test drives the built React portal in a real headless Chrome process, through localhost HTTP to Fastify and the disposable restricted-role PostgreSQL database. It reuses fictional disclosure fixtures. Browser cookies are provisioned from test sessions; no claim of sign-in/invitation acceptance is made.

Set `INVEOS_TEST_BROWSER=1` alongside the existing API test database variables after `npm run build`; run `npm test --workspace @inveos/api`. `INVEOS_CHROME_PATH` optionally selects a locally installed Chrome executable; default `/usr/bin/google-chrome`. CI enables this gate and uses its host-installed browser. There is no browser download, added package dependency, source redistribution, production access or external investigation. Browser version is logged as test evidence, not pinned or approved as a product runtime.

The harness uses Node's WebSocket with the [Chrome DevTools Protocol](https://chromedevtools.github.io/devtools-protocol/) to drive DOM controls, set fictional session cookies and allow download to a temporary test directory. Chrome's sandbox is left enabled: no `--no-sandbox`, security disabling or namespace workaround. Missing browser or sandbox failure causes the enabled test to fail. Local runs without the opt-in explicitly skip this browser scenario; skipped tests are not acceptance evidence.

Assertions cover actual portal rendering, recipient discovery, denied internal workspace access, real file download and SHA-256 equality, explicit checkbox/acknowledgement with durable database receipt, stale download denial after revocation, refreshed empty state and sign-out with subsequent unauthorised API access. Temporary browser profile/downloads, HTTP proxy and API listener are cleaned up. The localhost proxy serves only built assets and `/portal`, and forwards `/api` to the actual TCP listener; it supplies no mocked domain responses.

Run lint/types/build/foundation checks separately. Hosted run #77 passed the actual scenario in Chrome 155.0.8059.39 with the sandbox left enabled; all 122 Node tests ran with zero skips, alongside 42 Python tests and lint/types/build. Exact revision/tree and run link are recorded in BUILD_HANDOFF.md. Initial profile-cleanup failure was corrected with graceful browser shutdown and retried removal, and listener cleanup now executes even if browser cleanup fails. The CI test command has a 180-second hard lifetime bound. This is a bounded desktop Chrome portal scenario, not full investigator workspace, mobile/accessibility, identity, outage, restore or parser acceptance. No screenshots or artefacts containing session cookies are uploaded. Rollback removes the harness and CI opt-in without changing application records or migrations.

## Investigator extension

The shared localhost harness also serves the built investigator entry point. A separate fresh browser profile enters the development-only lab through its visible attestation, creates a fictional case, verifies original registration is disabled before authority, records two scope decisions through forms, reloads the selected case and signs out. PostgreSQL assertions require two distinct historical versions and unchanged first scope. Browser fetch after sign-out must return 401. The same scenario registers a fictional Unicode text file, proposes an exact source-linked claim, denies acceptance without a reason, accepts with a reason and downloads a JSON draft. The downloaded bytes must match the displayed fingerprint and pass the standalone Python verifier; tampering must fail. This is not production identity/MFA, PDF/OCR or complete product acceptance. Both tests use the same opt-in/run instructions and retain the sandbox and cleanup rules above. No schema or application changes; rollback removes the test extension.
