`GET /api/cases/:caseId/integrity-jobs` lists receipt metadata with `limit` (1–50, default 25) and optional `before` job UUID. It uses descending database `(created_at,id)` keysets, preserving timestamp precision under newer inserts. A cursor must belong to this case/tenant. No lease token, requester, idempotency key, object path or derivative content is returned. Status is a transaction-time observation; refresh to see subsequent worker changes.

`GET /api/cases/:caseId/integrity-jobs/:jobId/events` returns append-only recorded status, attempt, fixed failure code and server recording time. It pages in ascending sequence order with `limit` and optional `after` decimal sequence string (up to 18 digits). Sequence IDs remain strings to avoid JavaScript precision loss, and supplied cursors must belong to the exact job. Empty existing jobs differ from nonexistent jobs. Both routes require current internal case access, return no-store responses and use one repeatable-read transaction for access/cursor/results. Revocation after snapshot creation does not cancel an already in-flight response.
