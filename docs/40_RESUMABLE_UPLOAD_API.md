# Resumable binary upload API

Synthetic lab only; incremental on PR #20. No parser, dependency, production storage or browser chunk client.

POST `/api/cases/:caseId/uploads` reserves an actor-owned upload with filename, sourceTime (explicit timezone), method, expectedSha256 (lowercase), byteLength (1–262144) and idempotencyKey. It snapshots current authority. Repeating the same reservation key replays the receipt; changed metadata conflicts. There are at most ten open reservations per case, including expired reservations. Each expires after 24 hours.

GET `/api/cases/:caseId/uploads/:uploadId` returns status and received ordinal numbers, never staging bytes. POST its `/chunk` endpoint with ordinal and canonical contentBase64. Chunks are exactly 32768 bytes except the final reserved range; ordinals are 0–7. Out-of-order transfer and identical replay work; replacing an accepted chunk fails. State survives API restart. These routes require the original actor, current case membership and internal role; mutations require CSRF. Changed authority or expiry blocks further transfer/finalisation.

POST `/complete` with `{}` assembles all ranges, verifies the complete digest through the existing binary intake and writes the immutable quarantined original. Evidence, receipt audit, completed reservation and staging deletion commit together. Failures roll back database state and use existing original-file cleanup. Concurrent completion/replay returns the same evidence. Completed receipts reverify their original; no successful receipt is fabricated for a missing or corrupt object. A direct intake collision with the reservation UUID is rejected rather than silently completing an unrelated reservation.

POST `/cancel` with `{}` closes an open reservation, deletes only staging bytes and records one audit. Cancellation is allowed after expiry or authority replacement if the owner still has case access; terminal replay does not duplicate its audit. Completed originals cannot be cancelled or removed through this route. Expired staging is deliberately not silently deleted: cancel it to release capacity. Automatic expiry cleanup and administrator handling of revoked owners remain open. Staging payload is bounded to 2.5 MiB per case; total case count, completed metadata and audit volume remain unbounded as in the existing lab. Database staging is not encrypted object storage. No tenant-isolated SQL credentials/RLS are claimed.

Migration 011 adds reservation/chunk tables and immutable reservation identity/terminal guards. Existing evidence intake is factored into a shared function; the prior text and binary endpoints preserve their contracts. Finalisation rechecks reservation authority/status under the same case transaction as intake, preventing cancellation/scope changes between assembly and commit. Chunk bytes are transient staging, not evidence custody records. The case lock serialises reservation count and transfer changes. Filesystem/database crash atomicity remains the existing lab limitation; this does not prove power-loss recovery or restore.
