# Case disclosure oversight

28 October 2026. Synthetic lab slice stacked on PR #29. Reviewers need a durable history of what was disclosed, to whom, and what was subsequently acknowledged or withdrawn. This view does not create grants or identities.

`GET /api/cases/:caseId/disclosures?limit=25&before=<grant UUID>` requires a currently assigned reviewer. It returns at most 50 historical grants, including expired/revoked grants, ordered by database `(created_at,id)` descending. Cursors must belong to the same tenant and case. A withdrawn cursor remains usable. The query uses a consistent database snapshot and never rounds timestamps through JavaScript for ordering. Migration 018 adds a scoped history index.

Each row contains the grant/revision/recipient/issuer identities, fingerprint, authority version, reason, creation/expiry times, nullable acknowledgement time and nullable revocation actor/reason/time. It omits report bytes and request idempotency keys. No extra recipient profile directory is exposed. The `accessPolicyEligible` flag evaluates current authority, expiry, issuer assignment, recipient client role, dissent and revocation. It deliberately does not read/hash report bytes or imply an active session, confirmed download, legal permission or factual accuracy. Acknowledgement survives withdrawal as a historical assertion and does not approve findings.

The persistent Reports workspace includes a reviewer-only disclosure panel with refresh, older pages, receipt/revocation details and reasoned revocation through the existing CSRF-protected route. A successful revocation clears the stale page and instructs the reviewer to refresh. If the response is lost, inspect history before retrying; the existing endpoint preserves the first revocation and emits no duplicate event. No automatic revocation, release or notification is added. Already downloaded copies cannot be retracted.

Run normal migrations, then `npm run lint`, `npm run typecheck`, `npm run build`, `npm run test:foundation` and configured `npm run test:api`. Three new PostgreSQL scenarios cover actual HTTP after restart, historical acknowledgement/revocation, metadata minimisation, tied and microsecond cursor values, newer inserts, withdrawn anchors, role/tenant/case/cursor/query denials and issuer/authority changes. Hosted run #73 passed 121 Node tests, 42 Python tests and lint/types/build; exact implementation revision/tree and link are recorded in BUILD_HANDOFF.md. Browser acceptance, device/offline/restore and isolated parsers remain unrun.

Rollback can remove the history route and panel, retaining the harmless index and all original disclosure/audit records. No dependency, third-party source, collection, merge or deployment. Recipient administration, real identity, grant-creation UI with explicit scope controls, browser acceptance, redaction/final release artifacts and wider product gates remain open.
