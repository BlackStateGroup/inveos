Build branch: `feat/field-sessions`, based on bulk-processing `246007c6f4a86276497fd7ea98fb016bc7f97c63` (which includes device/sync `5063d97553ab77159e3b84bb798ac04d12b8631b`). Root owns integration and acceptance. This is a browser/API/offline implementation increment for the P0 Field session start/end and structured observation requirements in docs02 and WP04. It is not native, physical-device, production or entire-product acceptance.

## Implemented workflow

1. Unlock the existing encrypted Field vault and explicitly save current case scope. The account, tenant, case, software device, device version, grant version, case access version and authority remain pinned through the existing Field controls.
2. Start a session with a title, purpose, claimed event time, device-clock uncertainty, reason and scope confirmation. Save creates an immutable original JSON document, encrypted in the existing local capture store. It does not contact the server while offline. Session ID equals its start original's capture ID.
3. Select the session and record structured observations: title, category, first-hand/reported/supplied basis, account, source description, consent/authority declaration, claimed source time, uncertainty and reason. Optional location is manually entered only, with a necessary-purpose explanation, description, optional coordinate pair and known/unknown uncertainty. There is no geolocation API, watcher, automatic location, background capture or remote erasure.
4. Link up to ten existing original captures or case evidence items by exact ID and SHA-256, with source/media/context relation and link context. Files remain in the existing original intake/store. Links do not transcode, parse, approve, duplicate or replace bytes. Deliver linked captures before organising the observation. The server resolves each reference within the current case, verifies stored bytes/digest, and enforces existing registered-source use decisions.
5. Deliver the frozen original through the existing capture queue. Existing grant/device fences, independent lost-device recovery, current-account checks and exact original acceptance receipts remain in effect. The queue retains the full intake receipt object, including optional `fieldProvenance` added by root's parallel docs134 work; no receipt is reconstructed into a narrower object by this feature.
6. Explicitly organise the acknowledged original using a current device/case grant and a reason. This produces a separate immutable organisational receipt. A locally saved original, an acknowledged raw original and an acknowledged organisation record have distinct UI states. Start organisation precedes other session records; observation attachment delivery precedes their organisation. Retried/unknown requests retain their IDs and authority snapshots encrypted before sending. Exact receipt lookup is available after interruption/re-authentication.
7. End the selected session with an explicit event referencing the preceding session version. An end does not erase notes or infer a physical stop time from server time. UI blocks new observations after a locally known end, but the API can organise delayed original observations after end with an explicit `receivedAfterEnd` marker (meaning **organisation occurred after the end record**, not a claim about source chronology). Corrections remain available. Claimed end-before-start conflicts are shown without changing either time.
8. Append session organisation amendments or observation corrections/withdrawals. Session amendments retain their own claimed event time and context; they do not rewrite start/end source times. Every observation correction names its stable observation ID, exact preceding capture and version, and a correction reason. A withdrawal is another original containing the account and withdrawal reason; it is not deletion. Version conflicts reject organisation while leaving the raw original and local attempts intact. Read server history and deliberately prepare a new correction from the current exact version. Reference any abandoned conflicting original in the new reason; the failed original stays in the capture queue and server original store.
9. A different current case reviewer can inspect complete original/correction/attachment history and record a version-bound `context_checked` or `needs_correction` decision. Review rechecks current case authority/access and attachment integrity/source-use gates. Historical review never approves a new correction. Review does not create a finding, approve source use, change quarantine, release to a client, or claim admissibility. Verified-original download links reuse existing scoped audited download endpoints.

## Data and authority model

`packages/contracts/src/field-sessions.ts` defines the versioned first-party record format and strict shared validation. Only explicitly authored bounded JSON records are interpreted. Extra fields, automatic-location claims, malformed IDs, invalid calendar times, string versions, mismatched source/device identity, missing correction predecessors and unbounded input are rejected. This is not an external parser or parser benchmark.

Originals use the unchanged Field manifest/hash and intake API: `kind=field_note`, safe `.txt` filename, opaque immutable UTF-8 JSON original bytes. Raw source time, raw device time and clock uncertainty are independently retained. Server original receipt/ingest time, later organisation time and later review time are separate fields. Original authority remains historical even when recovery accepted the bytes under a newer independently approved authority. Organising **already acknowledged** bytes is a new explicit current-scope action; it cannot accept additional bytes or bypass the original recovery decision. Each organisation receipt records its separate current grant and reason.

Migration100 adds append-only `field_sessions` and `field_session_records`, scoped foreign keys, unique session/observation versions, unique original/request IDs and one end event per session. Migration101 adds append-only independent observation review receipts. Application writes hold the current case lock and recheck current membership; organisation also locks/checks the current device and grant. Original evidence and capture rows are never rewritten. Audit failure rolls back organisation/review rows atomically while separately committed original intake remains retained.

The server rejects a request ID reused for different input. The capture ID is also unique: a restored backup with a new organisation request ID receives the already retained receipt for the same verified original. Such receipt reconciliation is historical readback, not a new acceptance under a revoked device. Current case membership and original author are still checked on organise; GET receipt is available to internal current case members. Same-original replay/GET remains usable after grant expiry or revocation. New organisation is fenced. Case client roles, absent membership and other authors' mutation attempts are denied.

The vault keeps optional `journal` metadata inside the existing authenticated AES-GCM capture envelope. Original bytes and manifest are never mutated by journal updates. Writes compare encrypted record revision and vault identity; lock/replacement/concurrent-tab conflicts cannot silently overwrite another revision. Original intake acknowledgement preserves `journal` and the entire original receipt. Journal acknowledgement verifies exact raw record semantics, capture/evidence identity, manifest/raw hashes, author/case, source/device/receipt times and expected version before marking organisation acknowledged. Existing authenticated backup inventory, empty-vault restore and replacement-device re-encryption include journal data automatically. No IndexedDB schema migration or new cleartext store is introduced.

Raw original delivery errors use existing Field recovery controls. Organisation requests retain up to ten explicit authority/reason snapshots and twenty recent attempt summaries; exact originals and confirmed receipts are retained without eviction. Requests beyond bounds fail without overwriting prior state. HTTP failures leave the last durable request available for exact retry. Grant changes require explicit refreshed-scope organisation, not automatic retargeting. Independent online review keeps the unchanged request ID during a lost-response retry and exposes persisted review history after reload; it is not an offline review queue.

## Routes and limits

All routes are under the authenticated case scope; writes require CSRF.

| Method | Route below `/api/cases/:caseId` | Purpose |
| --- | --- | --- |
| POST | `/field-records` | Verify an acknowledged raw original and append session/observation organisation under a current grant |
| GET | `/field-records/:captureId/receipt` | Verify original bytes and read the exact organisational receipt |
| GET | `/field-sessions?before=<uuid>` | Case sessions, cursor pagination of 50 |
| GET | `/field-sessions/:sessionId` | Complete bounded session events, observation corrections and independent review history |
| POST | `/field-records/:captureId/reviews` | Exact-version independent context review, with stable ID/replay |

Bounds: 1,000 sessions per case; 250 retained organisation records per session (all events and correction versions); 20 review decisions per observation version; 10 attachments per observation; 12,000 characters per observation account; 1,000 as schema version ceiling. Session detail is complete within its enforced record bound; session list is paginated. Existing 256 KiB original, 100 local originals/contexts, 400,000-byte encrypted-envelope and device/grant/recovery bounds still apply. A queue-full error is not evidence deletion. Export encrypted backups early; browser persistent-storage grants are discretionary.

Session list/detail are retained projections, not a new full-store integrity sweep. Receipt GET, organisation and review verify applicable original bytes; attachments are verified when organised/reviewed and at their own original download. History inspection has its own audit event. No global tenant/operator dashboard or automatic collection is added.
