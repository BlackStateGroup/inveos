## Distinct permissions

Registering supplied capture context makes that original require a separate source-use decision before new interpretation, processing or release. Accepting metadata alone grants no use permission. An assigned independent reviewer records **internal analysis**, **analysis and approved client release**, or **block further use**, with a reason and bounded expiry. This records the organisation's decision; it does not independently establish legal sufficiency, source truth or a right to collect.

Permission pins the exact source metadata version/digest and acquisition authority. Granting it requires accepted current metadata, verified original bytes and a reviewer who authored no metadata revision. Terms/permission reference, purpose, lawful-basis note, scope, retention and minimisation are retained in that record. Expiry is 1–720 hours and cannot exceed recorded receipt time plus source retention. A block has no expiry and remains possible when the original is corrupt/unavailable or authority has changed. Later decisions preserve earlier ones. Changes to metadata, authority, metadata-reviewer or permission-reviewer access, withdrawal or expiry invalidate further permitted use. Every registered context for the same original must permit the requested use.

The Research source register shows the effective analysis/release states and decision history. Stable operation IDs recover lost responses; expected sequence and metadata identity prevent conflicting edits. Access denial clears loaded source context/editors. No URL is fetched or external message sent. Existing unregistered supplied originals remain governed by their acquisition authority; this increment is not a mandatory global connector registry. External collectors, live source requests, rate/source allowlists and independent approvals remain separate work.

## Enforced paths and retained history

New text/transcript/document interpretation, independent accepted interpretation, typed reasoning/chronology/graph source inspection, current report construction and frozen-source verification check permission. New extraction/index jobs, lease acquisition/renewal and derivative completion check analysis permission. A block stops a running leased worker and prevents further completion; original SHA-256 custody checks remain available. Extracted-source search/inspection checks current permission. Search facets and existing historical case records are retained metadata, not a fresh policy decision.

New frozen reports include the separately retained source-use decision, source context and metadata review. Changed decisions require a new revision for current verification/release. Explicit client disclosure additionally requires release permission; subsequent downloads and acknowledgements recheck it, for JSON, document packages and PDFs. Raw internal historical report/PDF downloads require current analysis permission. This does not erase earlier report bytes, original custody, prior derivatives, metadata/decision history or already downloaded copies. Client list discovery may show a previously approved grant whose next download is denied; this is not continued content access.

Migration 053 adds append-only, case-scoped source-use decisions with restricted SELECT/INSERT grants. Case locks serialise decisions with existing mutations and workers. Each decision and its audit event share a transaction; history is bounded at 100 decisions per registered source, with the final decision reserved for a terminal block so capacity exhaustion cannot retain an irrevocable approval. Granting permission requires Active/Review lifecycle; Closed/Archived cases cannot make new grants. No new dependency or upstream copy; existing INVEOS scoped metadata, decision and source-verification protocols are reused. Previously incorporated catalogue sources keep their actual pinned licence notices and provenance.

## Independent verification and limits

The standalone Python report verifier checks decision/metadata hashes, case/original/authority/version joins, independent declared actors, accepted metadata, non-blocked permission, expiry ordering, retention bounds and duplicate identities. The document-package verifier checks the same proof in mixed packages after verifying all source families. Actual API exports are checked by copied tools outside the repository with a separately retained report fingerprint. No runtime source collection or parser is substituted by these tests.

An offline proof checks recorded consistency, not current permission, actor authentication, actual legal approval or truth. A coherently rewritten proof or omitted optional field cannot be authenticated without the separately trusted whole-report fingerprint. Legacy report representation is unchanged when no registered source is cited. Keeping copies outside the server is not revoked by a later permission change.
